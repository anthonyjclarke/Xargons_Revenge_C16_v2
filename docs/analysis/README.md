## Codebase Index Fields

`codebase-index.json` holds:

- `assembly_roots`: modules in include order for `REVENGE` and `ASSEM-GRAPHS`.
- `modules`: path, fallback flag, raw bytes, logical lines, instruction lines and main-region bytes for each module.
- `symbols`: every definition with module, logical line, address and kind (`instruction-label`, `data`, `reserved`, `equate`).
- `variables`: each `VARS` and `EXTRA-MEMORY` reservation with address and size.
- `direct_transfers`: each `JSR`, `JMP` and branch with a symbolic operand and its resolved target.
- `self_modifying_stores`: stores whose operand resolves into an instruction.
- `counts`: the statistics quoted in [Codebase Analysis](../../CODEBASE_ANALYSIS.md#code-statistics-and-how-to-interpret-them).

Logical lines are CR-separated lines of the preserved module, numbered from 1. Module bytes are spans of `$1800–$379D` attributed through the assembler listing, so they include tables and text. Transfers are a list, not a call graph: they miss the self-modified IRQ dispatch, fall-through, returns and stack tricks. Self-modifying stores are found only from symbolic operands; writes through pointers aren't detected.

## Asset Data Fields

`asset-data.json` stores raw bytes as hex in memory order:

| Key                        | Contents                                 |
| :------------------------- | :--------------------------------------- |
| `aliens`                   | `BJH`, 1,024 bytes at `$0400`            |
| `aliens_running_version`   | The tape-loader variant of the same      |
| `landscape`                | `LANDSCAPE-2`, 256 glyphs at `$1000`     |
| `landscape_source_variant` | `ASSEM-GRAPHS` output, comparison only   |
| `font`                     | `FRAK!`, 256 glyphs at `$3800`           |
| `tables`                   | 56 named tables with address and length  |
| `movement_patterns`        | `PATD1`–`PATDG`, each ending in `$FF`    |
| `banner_provenance`        | `COMPACTOR` check against `TITLE-DATA`   |
| `gameplay_capture`         | RAM and colour variables at a VICE frame |
| `title_capture`            | Title screen RAM and colour variables    |

Glyphs are 8 bytes, top row first. Bit 7 is the leftmost pixel; in multicolour, bits 7–6 are the leftmost pair. The captures record the VICE run they came from and the hash of its memory dump.

## Reproduction and Verification

```bash
./build.sh
python3 scripts/verify_vice.py
python3 scripts/analyze_codebase.py
.venv/bin/python scripts/render_game_graphics.py
```

The analysis reads `build/` and the VICE captures, and fails if the running-version alien rule doesn't match the VICE dump. The renderer fails if the decoded title rows don't match a simulation of the title scroll, or if a rebuilt screen differs from a screenshot for a reason it can't classify. Both are deterministic: the same inputs give the same bytes, and the manifests record input and output hashes.
